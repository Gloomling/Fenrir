pyproject.toml
  Poetry package definition. Declares all dependencies, Python version constraint
  (≥3.10,<4.0), and two console-script entry points:
    fenrir      → fenrir.cli:main          (full CLI)
    fenrir-gui  → fenrir.fenrir_gui:launch_gui  (launches GUI directly)
  After `pip install -e .` both commands are available system-wide.

.env.example
  Template for API keys. Copy to .env and fill in:
    NVD_API_KEY           — National Vulnerability Database (free)
    VIRUSTOTAL_API_KEY    — VirusTotal threat intelligence (free tier)
    ALIENVAULT_OTX_API_KEY — AlienVault OTX threat feeds (free)
  All keys are optional. Fenrir uses offline data when keys are absent.

branding.json                           ← WRITTEN by fenrir_brand.py
  Persistent appearance configuration. Fenrir reads this on every launch.
  Contains: logo path, background path, opacity, all UI colours, font, title.
  This file is CREATED AND EDITED only by fenrir_brand.py — never by Fenrir itself.
  If absent, Fenrir uses built-in defaults.

fenrir_brand.py          ★ OPERATOR-ONLY TOOL
  Standalone branding GUI. Completely independent of the Fenrir package.
  No dependency on fenrir/* modules. Run it once to configure appearance,
  then distribute Fenrir to users — they see the result but cannot change it.
  See Section 5 for full details.

install_fenrir.sh
  Full Linux/macOS installer and desktop entry manager.
  Subcommands:
    install       — creates venv, pip installs, writes launchers + .desktop entry
    launch        — launches GUI directly
    desktop       — re-creates launchers and application menu entry only
    fix-desktop   — diagnoses and repairs .desktop visibility issues
    uninstall     — removes launchers and .desktop entries (preserves venv)

fenrir-gui.bat
  Windows double-click launcher. Sources the local venv automatically.
  Uses `pythonw` (no console window). Can be pinned to Start Menu or Taskbar.

fenrir-macos-launcher.sh
  macOS launcher script. Place in Fenrir.app/Contents/MacOS/ to create a
  proper .app bundle. Sources the venv and sets PYTHONPATH automatically.

fenrir.desktop
  XDG desktop entry TEMPLATE. The Exec= and Icon= fields contain placeholder
  text that install_fenrir.sh replaces with absolute paths at install time.
  DO NOT copy this file manually — use: ./install_fenrir.sh desktop
  Manual copies will fail to appear in menus (see Section 6 on .desktop issues).

fenrir/cli.py                                          981 lines
─────────────────────────────────────────────────────────
  Full argparse CLI. Every Fenrir scan module is accessible from the command line.
  Key functions:
    main()              — entry point: parses args, calls _run_scans or _handle_db_commands
    _build_parser()     — defines all CLI flags (-p, --modules, --gui, --db-*, etc.)
    _run_scans()        — async orchestrator: runs modules in dependency order
    _handle_db_commands()— --db-build, --db-update, --db-status, --db-build-source
  Key behaviours:
    fenrir <target>           — port scan + vuln scan (default)
    fenrir --gui              — launches the GUI
    fenrir <target> --all     — all modules
    fenrir --db-build         — build offline intelligence database
    Exit codes: 0=success, 1=scan error, 2=argument error

fenrir/fenrir_gui.py                                 3,386 lines
─────────────────────────────────────────────────────────
  Tkinter GUI application. Class FenrirGUI(tk.Tk).
  Reads branding.json via branding_config.py on startup — cannot edit it.
  
  Tabs:
    Scan          — _build_scan_tab(), _build_left_panel()
                    Target entry, module checkboxes, profile selector, Start/Stop
    Network Scan  — _build_network_tab()
                    Host discovery sweep → select hosts → deep assessment
    Results       — _build_results_tab(), _populate_results()
                    Sub-tabs: Ports / Vulnerabilities / Exploits / Recon / Threats
    History       — _build_history_tab(), _refresh_history_tab()
                    All past scans; diff two; open results folder
    Schedules     — _build_schedules_tab(), _check_schedules()
                    Add recurring scans; auto-fires every 60s while app is open
    Debug         — _build_debug_tab()
                    Per-module timing, memory gauge, raw log stream
    Database      — _build_db_tab()
                    Build/update offline DB, show record counts

  Key methods:
    _start_scan()         — validates, creates Results/YYYY-MM-DD_HH-MM_target/ dir,
                            records to history, launches scan thread
    _run_scan_async()     — async orchestrator with per-module timeout + semaphore
    _on_scan_done()       — saves to history, populates results, triggers EPSS enrichment
    _update_background()  — blends background image at branding-specified opacity
    _enrich_epss_async()  — fetches EPSS scores for all found CVEs post-scan
    _check_schedules()    — polls scheduled_scans table every 60s, fires due scans
    _show_exploit_guide() — double-click exploit row → full usage guide window
    launch_gui()          — module-level entry point called by CLI --gui and pip script

All scanner modules follow the same pattern:
  - One main class with async run() → list[dict]
  - Lazy-imported in modules/__init__.py via try/except (missing optional
    deps don't crash the app)
  - Registered in MODULE_REGISTRY for CLI and GUI checkbox binding

fenrir/network_scanner.py                            1,673 lines
─────────────────────────────────────────────────────────
  Classes: HostInfo (dataclass), NetworkScanner.
  HostInfo fields: ip, mac, mac_vendor, hostname, os_name, os_family,
    os_version, open_ports, services, device_class, device_subclass,
    cves, exploits, banners, ttl, is_up, scan_time
  NetworkScanner methods:
    discover_hosts(target_spec) → list[HostInfo]  — fast sweep only
    run(target_spec, modules, output_dir) → list[HostInfo]  — full pipeline
    assess_one(ip) → HostInfo  — single host full assessment
    _assess_host()  — full Phase A/B/C/D/E pipeline:
      Phase A: port scan (nmap -sV or TCP connect fallback)
      Phase B: CVE lookup per service
      Phase C: OS fingerprinting (5-layer approach):
                1. ostype from nmap -sV XML service elements
                2. Banner inference (SSH/HTTP/SMB/CPE patterns)
                3. nmap --script smb-os-discovery (Windows, port 445)
                4. nmap -O --osscan-guess (requires root/CAP_NET_RAW)
                5. TTL heuristic fallback (Linux≤64, Windows≤128, Cisco≤255)
      Phase D: exploit matching against offline DB for every found CVE
      Phase E: device classification (IoT/Server/Router/Workstation/etc.)

8. DESKTOP ENTRY (.desktop) — WHY IT MAY NOT APPEAR AND HOW TO FIX IT
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

The .desktop file is a Linux/freedesktop standard for application menu entries.
Eight things commonly cause it to be invisible:

  1. Exec= is a bare command name, not an absolute path
     ✗ Exec=fenrir-gui
     ✓ Exec=/home/user/fenrir/fenrir-gui.sh
     Why: Desktop environments search $PATH inconsistently. Absolute paths always work.

  2. TryExec= missing
     If TryExec= points to a binary that doesn't exist, some DEs hide the entry silently.
     ✓ TryExec=/home/user/fenrir/fenrir-gui.sh  (same as Exec=)

  3. Icon= name not in GTK icon cache
     ✗ Icon=fenrir                    (only works if fenrir.png is in the icon theme)
     ✓ Icon=/home/user/fenrir/assets/logo.png  (absolute path always works)
     Fix: gtk-update-icon-cache -f -t ~/.local/share/icons/hicolor

  4. Windows CRLF line endings
     .desktop files with \r\n are silently ignored by freedesktop parsers.
     Fix: sed -i 's/\r//' ~/.local/share/applications/fenrir.desktop
     The install_fenrir.sh script uses printf to guarantee LF endings.

  5. File not marked executable
     GNOME and some other DEs require .desktop files to be chmod +x.
     Fix: chmod +x ~/.local/share/applications/fenrir.desktop

  6. GNOME "Untrusted application" flag
     GNOME Nautilus marks newly-added .desktop files as untrusted.
     Fix: gio set fenrir.desktop metadata::trusted true

  7. update-desktop-database not run
     The MIME/application cache must be rebuilt after adding a .desktop file.
     Fix: update-desktop-database ~/.local/share/applications

  8. xdg-desktop-menu not called
     Simply copying a .desktop file to the applications directory is unreliable.
     Fix: xdg-desktop-menu install --novendor fenrir.desktop

  install_fenrir.sh applies all 8 fixes automatically.
  If the entry still doesn't appear after install:
    - Run: ./install_fenrir.sh fix-desktop     (diagnoses all 8 causes)
    - Or:  Log out and back in (most reliable)
    - Or:  Press Alt+F2, type 'r', Enter       (GNOME Shell restart)
    - Or:  Run: xdg-desktop-menu forceupdate

11. ADDING A NEW SCANNER MODULE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  1. Create fenrir/my_scanner.py with class MyScanner
  2. Implement: async run(target, **kwargs) → list[dict]
  3. Add try/except import block in fenrir/modules/__init__.py
  4. Add key to MODULE_REGISTRY in modules/__init__.py
  5. Add GUI checkbox in _build_left_panel() in fenrir_gui.py
  6. Add CLI flag in _build_parser() in cli.py
  7. Add timeout in MODULE_TIMEOUTS dict in fenrir_gui.py (if slow)
  8. Optionally add to HEAVY_MODULES set if it uses significant memory

  The module will then automatically appear in both CLI and GUI,
  be subject to the global timeout, run inside the concurrency semaphore,
  and have its results saved to the Results/ directory and history DB.
